= Perguntas frequentes sobre o ONTAP tools for VMware vSphere
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs:

[role="lead"]
Este FAQ responde a perguntas comuns sobre o ONTAP tools for VMware vSphere. Ele aborda conceitos, implantação, backends de storage, proteção de datastore e automação que são úteis ao implantar, gerenciar e solucionar problemas no seu ambiente do ONTAP tools.



[[deployment-and-high-availability]]
== Implantação e alta disponibilidade

.Quais versões do VMware vSphere, do ESXi e do ONTAP são compatíveis com o ONTAP tools?
As versões compatíveis do ONTAP, do ESXi e do vCenter Server variam de acordo com a versão das ferramentas ONTAP. O host ESXi e o vCenter Server usados para implantar a máquina virtual das ferramentas ONTAP também podem ter requisitos separados e mais restritivos do que as versões que as ferramentas ONTAP podem gerenciar após a implantação. As versões compatíveis mudam entre versões, portanto, sempre verifique o https://mysupport.netapp.com/matrix["Ferramenta de Matriz de interoperabilidade do NetApp"^] e o link:deploy/prerequisites.html["Ferramentas ONTAP para requisitos e limites de configuração do VMware vSphere"] da versão que você está executando.

.Qual versão do ONTAP tools devo usar, 9.x ou 10.x?
A maioria dos ambientes se beneficia da migração para a versão mais recente do ONTAP tools 10.x. Em comparação com o ONTAP tools 9.13, ela adiciona suporte a NVMe-oF para VMFS, é qualificada para versões mais recentes do ONTAP e do VMware vSphere e oferece suporte a várias instâncias do vCenter Server por appliance, em vez de apenas uma. Permanecer no ONTAP tools 9.x só faz sentido se o seu ambiente tiver uma dependência específica que a versão 10.x mais recente ainda não oferece suporte, e vale a pena planejar a migração o quanto antes, já que o ONTAP tools 9.x está se aproximando do fim do suporte. Consulte a página  https://mysupport.netapp.com/site/info/version-support["Site de suporte da NetApp - suporte à versão do software"^] para ver as datas atuais de fim do suporte. Consulte link:release-notes/ontap-tools-9-ontap-tools-10-feature-comparison.html["Comparação de recursos das ferramentas ONTAP para VMware vSphere por versão"] e  https://mysupport.netapp.com/matrix["Ferramenta de Matriz de interoperabilidade do NetApp"^] para confirmar qual versão corresponde às suas versões do ONTAP, ESXi e vSphere.

.Como posso expandir a implementação do ONTAP tools à medida que minhas necessidades crescem?
O ONTAP tools é sempre implantado inicialmente como um appliance extra pequeno (XS) de nó único, fornecendo serviços principais para datastores NFS e VMFS. Se depois você precisar de mais recursos, maior resiliência ou vVols e HA, poderá escalá-lo para pequeno, médio ou grande, ou expandi-lo para HA; as implantações de HA são multinós, usam três nós e exigem uma biblioteca de conteúdo, e as implantações grandes são compatíveis apenas com HA. Para oferecer suporte à expansão de HA, implante o appliance em um cluster ESXi ou pool de recursos e certifique-se de que o hot-add de CPU e o hot-plug de memória estejam habilitados; a partir do ONTAP tools 10.6, as novas implantações habilitam essas configurações por padrão. Os recursos de CPU, memória e disco para cada tamanho estão listados em link:deploy/prerequisites.html["Ferramentas ONTAP para requisitos e limites de configuração do VMware vSphere"], portanto, é seguro começar com o padrão XS e expandir à medida que seus requisitos aumentam. O ONTAP tools oferece suporte apenas ao escalonamento vertical: você só pode aumentar o tamanho do nó, não reduzi-lo, e depois de habilitar o HA, não pode reverter para uma configuração sem HA de nó único. Para as etapas de implantação, dimensionamento e expansão, consulte link:deploy/quick-start.html["Início rápido das ferramentas do ONTAP para VMware vSphere"], link:deploy/ha-workflow.html["Fluxo de trabalho de implantação de alta disponibilidade para ONTAP tools"] e link:manage/edit-appliance-settings.html["Aumente as ferramentas ONTAP e habilite a alta disponibilidade"].

.O que a alta disponibilidade protege e o que você deve levar em consideração?
A solução de HA foi projetada para ajudar você a se recuperar de uma falha de host de nó único, falha de rede, falha do sistema operacional convidado ou falha do aplicativo ONTAP tools. As implementações de HA usam três nós, que devem estar na mesma sub-rede para a comunicação entre nós. CPU hot-add e memory hot-plug devem estar habilitados; o fluxo de trabalho de HA também exige o VASA Provider para datastores vVols. Consulte link:deploy/ha-workflow.html["Fluxo de trabalho de implantação de alta disponibilidade para ONTAP tools"] para ver as etapas de configuração.

.Preciso de uma implementação de alta disponibilidade (HA) e quando devo usá-la?
A HA não é necessária se você estiver usando apenas datastores NFS ou VMFS sem vVols, mas ainda assim ela oferece maior resiliência contra falhas de host de nó único, de rede, do sistema operacional convidado ou do aplicativo ONTAP tools. A HA é necessária para manter o serviço do VASA Provider continuamente disponível para datastores vVols, portanto, use uma implementação de HA se você usar vVols ou se precisar de maior resiliência do serviço e de mais contêineres por serviço do que uma implementação de nó único oferece.

.Uma única implantação do ONTAP tools 10.x pode gerenciar várias instâncias do vCenter Server?
Sim. Ao contrário do ONTAP tools 9.x, que oferece suporte a apenas um vCenter Server por appliance, o ONTAP tools 10.x oferece alocação a vários clientes e permite que você gerencie várias instâncias do vCenter Server em uma única interface do ONTAP tools Manager, reduzindo o número de appliances e os requisitos gerais de recursos. Se você usar datastores vVols em várias instâncias do vCenter Server, atualize o certificado autoassinado para um certificado assinado por uma CA para uma comunicação segura. Consulte link:configure/add-vcenter.html["Adicionar instâncias do vCenter Server às ferramentas ONTAP"] para ver as etapas.



[[networking-and-ports]]
== Rede e portas

.De quantos endereços IP uma implementação do ONTAP tools precisa e para que serve cada um deles?
Uma implementação de nó único requer três endereços IPv4 estáticos e exclusivos na mesma sub-rede:

* *IP do ONTAP tools* (anteriormente o IP do balanceador de carga): o endpoint externo para o ONTAP tools Manager (`https://<ONTAPtoolsIP>:8443/virtualization/ui/`), a API REST, o VASA Provider, o Storage Replication Adapter (SRA) e o plug-in do cliente vSphere.
* *IP virtual do ONTAP tools* (anteriormente, o IP de interconexão de nós): atribuído ao servidor da API do Kubernetes e usado como IP virtual para o plano de controle do Kubernetes.
* *IP do nó*: o endereço de gerenciamento do nó usado para acesso ao shell de diagnóstico e SSH.


Uma implementação de HA adiciona um endereço IP de nó adicional para cada um do segundo e do terceiro nós; o endereço IP do ONTAP tools e o IP virtual são compartilhados entre todos os nós. Consulte link:deploy/prerequisites.html["Ferramentas ONTAP para requisitos e limites de configuração do VMware vSphere"] e link:deploy/pre-deploy-checks.html["Requisitos de pré-implantação para ONTAP tools"] para ver a planilha completa de implementação.

.Quais portas de rede o ONTAP tools usa?
O ONTAP tools expõe as portas 443 e 8443 como portas de passagem externas para o ONTAP tools Manager, a API REST, o VASA Provider e o back-end do plug-in do vSphere Client. As demais portas na tabela de requisitos de portas são portas entre nós usadas internamente pelo cluster Kubernetes do appliance; em uma implantação de nó único, elas não exigem acesso externo e, em uma implantação de HA, todos os três nós devem conseguir se comunicar entre si por essas portas, incluindo a UDP 8472 para a comunicação entre pods. Consulte link:deploy/prerequisites.html["Ferramentas ONTAP para requisitos e limites de configuração do VMware vSphere"] para ver a tabela completa de portas.



[[certificates-and-security]]
== Certificados e segurança

.O que as ONTAP tools exigem do certificado do servidor vCenter Server?
Um certificado só protege uma conexão se comprovar a identidade do servidor ao qual você está se conectando. A extensão Nome Alternativo do Assunto (SAN) fornece essa comprovação: ela lista os nomes DNS e endereços IP para os quais o certificado é válido.

O certificado SSL da máquina do servidor vCenter deve atender aos seguintes requisitos:

* A SAN inclui o nome DNS e o endereço IP do vCenter Server.
* A SAN inclui o vCenter Identificador de Rede Primária do Servidor (PNID), e o PNID corresponde ao nome DNS.
* Todos os nomes na SAN são resolvidos no DNS.


Se o certificado não tiver SAN, ou se o SAN não corresponder ao nome DNS, ao endereço IP ou ao PNID do Server vCenter, as operações do ONTAP tools falharão com erros de validação de certificado. Essa validação não pode ser desativada. Corrija o SAN com o vSphere Certificate Manager antes de adicionar a instância do Server vCenter. Consulte link:configure/add-vcenter.html["Adicionar instâncias do vCenter Server às ferramentas ONTAP"] para ver os requisitos e exemplos de certificados.

.Por que a adição de um backend de storage falha na validação do certificado, e como você pode corrigir isso?
As ONTAP tools validam os certificados do backend de armazenamento por padrão, pelo mesmo motivo que validam os certificados do servidor vCenter Server: a extensão SAN comprova a qual cluster ou LIF de gerenciamento de SVM o certificado pertence. O certificado autoassinado padrão do ONTAP geralmente não tem SAN, portanto a validação falha quando você adiciona o backend de armazenamento.

Para resolver uma falha de validação:

* Substitua o certificado por um cujo SAN inclua o endereço IP ou o nome DNS do LIF de gerenciamento do cluster ou da SVM e, em seguida, busque e autorize o certificado atualizado ao adicionar ou readicionar o backend de armazenamento.
* Se não for possível substituir o certificado imediatamente, desative a validação do certificado no console de manutenção. Isso ignora a validação para todos os backends de armazenamento configurados e não se aplica aos certificados do servidor vCenter Server.


Se um certificado de backend de armazenamento expirar antes de você renová-lo, o ONTAP tools marcará o backend de armazenamento como desconhecido, pois ele não conseguirá mais se conectar ao sistema de storage. Consulte link:configure/add-storage-backend.html["Adicionar um backend de armazenamento às ferramentas ONTAP"] e link:manage/change-valid-flag.html["Alterar sinalizador de validação de certificado"] para ver as etapas.



[[datastores-and-storage-backends]]
== Datastores e backends de storage

.Quais tipos de datastore e protocolos posso gerenciar?
As ONTAP tools oferecem suporte a estes tipos de datastore e protocolos:

* *NFS*: NFSv3 e NFSv4.1.
* *VMFS*: iSCSI, FC, NVMe/TCP e NVMe/FC.
* *vVols*: provisionados e gerenciados por meio do VASA Provider.


Consulte link:configure/create-datastore.html["Criar um datastore nas ONTAP tools"] para obter as etapas de criação.

.Por que as ONTAP tools criam tantos igroups, e posso usar meus igroups simples existentes?
As ONTAP tools utilizam, por definição, um modelo de igroup aninhado:

* Um igroup pai representa o acesso de cada datastore, e um igroup filho representa cada host ESXi. Os mapeamentos de LUN se aplicam ao igroup filho.
* Essa estrutura permite que as ONTAP tools reutilizem o igroup filho de um host em vários datastores, em vez de duplicar o acesso do host para cada datastore, e fornece às ONTAP tools o controle granular por host de que elas precisam para operações de montagem, desmontagem e atualização de host.
* Os igroups gerenciados pelo ONTAP tools usam o prefixo  `otv_`.


Se você já tiver igroups simples mapeados para datastores que as ONTAP tools descobrem, as ONTAP tools os convertem durante a descoberta: elas mantêm o igroup original como um igroup filho renomeado com o `otv_` prefixo e criam um igroup pai acima dele, sem alterar os mapeamentos de iniciador subjacentes. Os igroups que não estão mapeados para um datastore, como igroups de LUN de inicialização, permanecem inalterados.

Como o ONTAP tools depende dessa estrutura pai-filho para rastrear o acesso do host, não renomeie, edite nem exclua manualmente os igroups gerenciados pelo ONTAP tools. Em vez disso, use os fluxos de trabalho de montagem, desmontagem e atualização de host do ONTAP tools. Consulte link:manage/nested-igroups.html["Gerenciamento de igroups aninhados nas ONTAP tools"] e link:manage/igroup-workflow.html["Como as ONTAP tools gerenciam igroups e políticas de exportação"] para obter detalhes.

.Qual a diferença entre um backend de armazenamento global e um backend de armazenamento local?
Os backends de storage diferem em escopo e credenciais:

* *Backend de storage global*: adicionado uma única vez no ONTAP tools Manager usando apenas as credenciais do cluster do ONTAP. Ele não fica vinculado a um servidor vCenter até que você o associe a um, e fornece a descoberta em nível de cluster de que o gerenciamento de vVols precisa.
* *Backend de armazenamento local*: adicionado por vCenter Server usando credenciais de cluster ou SVM e disponível apenas para esse vCenter Server. As credenciais SVM sozinhas são suficientes para datastores VMFS e fluxos de trabalho do Storage Replication Adapter (SRA), mas não para vVols.


Veja link:configure/add-storage-backend.html["Adicionar um backend de armazenamento às ferramentas ONTAP"] e link:configure/associate-storage-backend.html["Associe um backend de armazenamento a uma instância do servidor vCenter nas ONTAP tools"] para ver as etapas.

.O que preciso para usar vVols com as ONTAP tools?
Os fluxos de trabalho do datastore de vVols dependem de o serviço VASA Provider estar ativado e registrado no servidor vCenter selecionado. As ONTAP tools usam o VASA Provider para criar e manter a representação do datastore de vVols, e as políticas de storage de VM usam regras do provedor de tipo de storage NetApp vVols. Em uma configuração de HA, o fluxo de trabalho de HA também requer o VASA Provider para datastores de vVols. Consulte link:manage/enable-services.html["Ativar serviços opcionais no ONTAP tools Manager"] e link:configure/registration-process.html["Registre o provedor VASA com uma instância do vCenter Server nas ONTAP tools"] para ver as etapas de configuração.

.A VMware descontinuou vVols. O que isso significa para os usuários do ONTAP tools?
A Broadcom descontinuou vVols a partir do VMware Cloud Foundation e do VMware vSphere Foundation 9.0 e planeja descontinuar o recurso em uma versão futura. Para novas implantações, planeje usar datastores VMFS ou NFS e deixe o VASA Provider desativado, a menos que você use atualmente vVols. Verifique nas notas de versão do ONTAP tools o suporte a vVols em cada versão.



[[protection-and-disaster-recovery]]
== Proteção e recuperação de desastres

.Como posso proteger datastores usando o ONTAP tools for VMware vSphere?
Você pode proteger um datastore VMFS qualificado que usa o protocolo iSCSI ou FC adicionando-o a um grupo de proteção com uma relação do SnapMirror, usando uma política Asynchronous ou AutomatedFailOverDuplex. Quando um cluster de hosts contém datastores de várias SVMs, use o fluxo de trabalho de proteção granular de datastore para selecionar e proteger datastores no nível do grupo de proteção. Consulte link:manage/protect-ds.html["Proteja um datastore VMFS nas ONTAP tools"] e link:protect/protect-multiple-ds.html["Proteja datastores em um cluster com ONTAP tools"] para ver as etapas.

.Como posso usar as ferramentas do ONTAP para recuperação de desastres?
Para recuperação de desastres baseada em array, habilite o serviço SRA nas ONTAP tools e instale o adaptador SRA no appliance VMware Live Site Recovery. Use os mesmos agendamentos personalizados do SnapMirror nos clusters de origem e de destino antes de executar os fluxos de trabalho do SRA. Em uma nova configuração do SRA, sempre execute um failover de teste; ignorá-lo pode fazer com que a operação de reproteção falhe. Consulte link:protect/enable-storage-replication-adapter.html["Configure o SRA nas ONTAP tools para proteger datastores"] para ver as etapas de configuração.

.Quais tipos de datastore posso proteger com o SRA e o VMware Live Site Recovery?
O SRA oferece suporte a datastores NFSv3 e datastores VMFS em iSCSI e FC. A recuperação de desastres não é compatível com datastores NVMe-oF, e o VMware Live Site Recovery não oferece suporte à replicação baseada em arrays para NFSv4.1 ou datastores FlexGroup. Os grupos de consistência são compatíveis apenas com iSCSI e FC; adicionar volumes NFS a um grupo de consistência faz a descoberta de dispositivos falhar.

.Qual é a diferença entre a proteção de active sync do SnapMirror e a recuperação de desastres baseada em SRA?
O fluxo de trabalho de proteção do cluster de host usa o SnapMirror active sync para datastores VMFS. O ONTAP tools 10.6 também oferece suporte à proteção granular de datastores, o que permite selecionar datastores VMFS qualificados usando iSCSI ou FC e aplicar a proteção no nível do grupo de proteção. O SRA se integra ao VMware Live Site Recovery para fluxos de trabalho de recuperação de desastres baseados em array. Consulte link:protect/granular-datastore-protection-concept.html["Critérios granulares de elegibilidade para proteção de datastore nas ferramentas ONTAP"] para ver detalhes de qualificação.



[[access-control-backup-and-support]]
== Controle de acesso, backup e suporte

.Como o controle de acesso funciona entre as ONTAP tools, o vCenter e o ONTAP?
O acesso é controlado em dois ambientes: as permissões do servidor vCenter controlam o acesso aos objetos do vSphere, e as funções do ONTAP controlam as operações de storage. As ONTAP tools verificam primeiro a função do vCenter e, em seguida, verificam a função do ONTAP associada ao backend de storage. As ONTAP tools não criam contas de usuário no vCenter nem no ONTAP, portanto, os administradores criam as contas de serviço necessárias. Consulte link:concepts/rbac-learn-about.html["Saiba mais sobre RBAC nas ferramentas ONTAP"] para obter mais informações.

.Como configurar o controle de acesso baseado em funções (RBAC) no ONTAP tools for VMware vSphere?
Como o ONTAP tools não cria contas de usuário no vCenter ou no ONTAP, um administrador do vSphere deve criar as contas de serviço necessárias e atribuir funções em ambos os ambientes. No vCenter Server, o ONTAP tools estende o modelo RBAC com objetos adicionais expostos por meio do plug-in remoto. No ONTAP, o acesso é controlado por uma função do ONTAP atribuída ao usuário que você fornece ao autenticar um backend de armazenamento; o ONTAP tools fornece funções predefinidas e arquivos de função JSON que você pode usar para atribuir os privilégios mínimos necessários para operações de backend de armazenamento. Consulte link:concepts/rbac-vcenter-use.html["Como o RBAC do vCenter Server funciona com ONTAP tools for VMware vSphere"] e link:configure/configure-user-role-and-privileges.html["Configure funções e privilégios de usuário do ONTAP para ONTAP tools"] para ver as etapas de configuração.

.Com que frequência as ONTAP tools fazem backup do dispositivo e para que esse backup serve?
A partir do o ONTAP tools 10.5, os backups são ativados por padrão e executados a cada 10 minutos. Os arquivos de backup são armazenados no datastore e permitem que você reimplante e recupere o próprio appliance do ONTAP tools caso a máquina virtual original seja perdida; eles não são um backup do cluster do ONTAP nem da configuração do servidor vCenter que o ONTAP tools gerencia. Você pode alterar a frequência para entre 10 e 60 minutos. Consulte link:manage/backup-settings.html["Editar configurações de backup das ferramentas ONTAP"] e link:manage/recover-backup.html["Recupere as ONTAP tools for VMware vSphere a partir do backup"] para ver as etapas.

.Posso desativar os backups do ONTAP tools?
Você pode, mas não desative os backups, porque isso impede que as ONTAP tools mantenham um objetivo de ponto de recuperação baixo. Desativar os backups não exclui os arquivos de backup existentes. Consulte link:manage/backup-settings.html["Editar configurações de backup das ferramentas ONTAP"] para ver as etapas.

.Onde posso encontrar os logs quando precisar solucionar problemas ou entrar em contato com o suporte?
Você pode gerar um pacote de logs no ONTAP tools Manager ou no vSphere Client. Um pacote gerado no ONTAP tools Manager inclui logs de todas as instâncias gerenciadas do vCenter Server; um pacote gerado no vSphere Client é limitado ao vCenter Server selecionado. Baixe o arquivo gerado e forneça-o ao suporte técnico quando solicitado. Consulte link:deploy/deployment-error-codes.html["Códigos de erro de implantação das ferramentas ONTAP"] para ver as etapas.

.Como posso coletar informações de diagnóstico para solucionar problemas com as ONTAP tools?
Além do pacote de logs, você pode habilitar o acesso remoto para diagnóstico (SSH) à conta de usuário  `diag` no console de manutenção. Só é permitida uma sessão de login de diagnóstico por vez, e o acesso é desativado automaticamente à meia-noite do dia seguinte ou assim que você fizer login novamente como o usuário de diagnóstico. Use esse acesso para uma solução de problemas mais aprofundada do que a que um pacote de logs oferece e gere primeiro um pacote de logs para que o suporte técnico tenha os logs de referência com que trabalhar. Consulte link:manage/configure-remote-diagnostic-access.html["Configure o acesso remoto para diagnóstico das ONTAP tools"] para ver as etapas.



[[upgrade-migration-and-automation]]
== Atualização, migração e automação

.Posso atualizar diretamente para a versão mais recente do ONTAP tools 10.x?
A atualização direta é suportada nas duas versões imediatamente anteriores à versão mais recente (N-2). Se a sua versão estiver mais desatualizada, primeiro atualize para a versão mais antiga que oferece suporte a uma atualização direta para a versão mais recente e, em seguida, atualize novamente para a versão mais recente. Habilite o backup de baixo RPO e faça o download do backup antes de iniciar, pois uma atualização com falha nem sempre pode ser revertida, e a recuperação então depende do backup de baixo RPO ou da recuperação de snapshot. Consulte link:upgrade/upgrade-ontap-tools.html["Atualize das ONTAP tools for VMware vSphere 10.x para 10.6"] para ver os caminhos e as etapas de atualização compatíveis.

.Como posso migrar do ONTAP tools 9.x para a versão 10.x mais recente?
A migração é suportada apenas de versões específicas do ONTAP tools 9.x. O caminho de migração depende de seu ambiente usar vVols: ambientes com vVols migram o VASA Provider e atualizam o SRA, enquanto ambientes com apenas datastores NFS e VMFS removem a implantação 9.x e implantam a 10.x. Os datastores vVols que usam NVMe/FC ficam inoperantes após a migração porque o ONTAP tools 10.x oferece suporte a NVMe-oF apenas com datastores VMFS. Consulte link:migrate/migrate-to-latest-ontaptools.html["Migrar das ONTAP tools for VMware vSphere 9.xx para 10.6"] para ver as versões de origem e as etapas compatíveis.

.Posso automatizar as operações do ONTAP tools com uma API REST?
Sim. O ONTAP tools fornece uma API REST para automação, separada da API REST do cluster ONTAP. O acesso à API usa o endereço IP e a porta 8443 do ONTAP tools; autentique-se com as credenciais do ONTAP tools Manager para obter um token de acesso e, em seguida, envie o token no  `x-auth` cabeçalho. Operações de longa duração podem ser executadas de forma assíncrona e retornar um job para você monitorar. Consulte link:automation/learn-rest-api.html["Saiba mais sobre a API REST do ONTAP tools"] e link:automation/first-call.html["Faça sua primeira chamada à API REST das ONTAP tools"] para começar.
