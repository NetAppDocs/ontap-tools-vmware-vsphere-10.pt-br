= Implantar ONTAP tools
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Implante ONTAP tools for VMware vSphere como um appliance de nó único extra pequeno que oferece suporte a datastores NFS e VMFS. O processo de implantação leva até 45 minutos.

.Antes de começar
Se você implantar uma configuração de nó único extrapequena, uma biblioteca de conteúdo é opcional. Para implantações com vários nós ou de alta disponibilidade, uma biblioteca de conteúdo é obrigatória.

No VMware, uma biblioteca de conteúdo armazena modelos de máquina virtual, modelos de vApp e outros arquivos. Usar uma biblioteca de conteúdo simplifica a implantação porque não depende do acesso à rede durante as operações com modelos.

Antes de criar uma biblioteca de conteúdo:

* Crie a biblioteca de conteúdo em um armazenamento de dados compartilhado para que todos os hosts no cluster possam acessá-la.
* Crie a biblioteca de conteúdo antes de implantar o ONTAP tools for VMware vSphere OVA.
* Mantenha o modelo OVA na biblioteca de conteúdo após a implantação.



NOTE: Se você planeja habilitar o HA posteriormente, implante a máquina virtual das ONTAP tools em um cluster ESXi ou pool de recursos, não diretamente em um host ESXi.

Para criar uma biblioteca de conteúdo:

. Baixe os binários do ONTAP tools for VMware vSphere (_.ova_) e os certificados assinados do  https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Site de suporte da NetApp"^].
. Faça login no vSphere Client.
. No menu do vSphere Client, selecione *Bibliotecas de conteúdo*.
. Selecione *Criar*.
. Insira um nome e crie a biblioteca de conteúdo.
. Abra a biblioteca de conteúdo que você criou.
. Selecione *Ações* > *Importar item* e importe o arquivo OVA.



NOTE: Para mais informações, consulte  https://blogs.vmware.com/vsphere/2020/01/creating-and-using-content-library.html["Criando e usando a Biblioteca de conteúdo"].


NOTE: Antes da implantação, defina o Distributed Resource Scheduler (DRS) do cluster como conservador para evitar a migração de máquinas virtuais durante a instalação.

ONTAP tools for VMware vSphere é inicialmente implementado como uma configuração sem HA. A partir do ONTAP tools 10.6, adicionar CPU sem desligamento e adicionar memória sem desligamento estão habilitados por padrão. Para escalar para HA depois, esses recursos devem ser habilitados.

.Passos
. Baixe o arquivo OVA das ONTAP tools e os certificados assinados do  https://mysupport.netapp.com/site/products/all/details/otv10/downloads-tab["Site de suporte da NetApp"^]. Se você já importou o OVA para sua biblioteca de conteúdo, ignore esta etapa.
. Faça login no servidor vSphere.
. Acesse o pool de recursos, cluster ou host onde você deseja implantar o OVA.
+

IMPORTANT: Não armazene a máquina virtual do ONTAP tools em datastores vVols que ela gerencia.

. Implante o OVA a partir da biblioteca de conteúdo ou do sistema local.
+
|===


| Do sistema local | Da biblioteca de conteúdo 


| a. clique com o botão direito do Mouse e selecione *Deploy OVF template...*. b. escolha o arquivo OVA no URL ou navegue até seu local e selecione *Next*. | r. vá para a biblioteca de conteúdo e selecione o item da biblioteca que você deseja implantar. b. Selecione *ações* > *Nova VM a partir deste modelo* 
|===
. Em *Selecione um nome e uma pasta*, insira o nome e o local da máquina virtual.
. Selecione um recurso de computador e selecione *Next*. Opcionalmente, marque a caixa para *ligar automaticamente a VM implantada*.
. Revise os detalhes do modelo e selecione *Next*.
. Leia e aceite o contrato de licença e selecione *Next*.
. Selecione o armazenamento para a configuração e o formato do disco e selecione *Next*.
. Selecione a rede de destino para cada rede de origem e selecione *seguinte*.
. Na janela *Personalizar modelo*, insira os valores necessários. image:../media/custom-temp-p2.png["Personalizar modelo"]
+
[IMPORTANT]
====
Os valores na página *Personalizar modelo* são obrigatórios para uma implementação bem-sucedida.

Preste especial atenção a estes campos:

** *Nome do host*: Insira o nome do host da VM ONTAP tools. Use um formato de nome de host válido.
** *Endereço IP das ONTAP tools*: Esta é a interface de gerenciamento principal usada para acessar as ONTAP tools.
** *Endereço IPv4*: Este é o endereço IP do nó usado para acesso ao shell de diagnóstico e SSH para resolução de problemas e manutenção.


Se você usar nomes DNS para o host ou vCenter, certifique-se de que esses nomes sejam resolvidos corretamente no DNS.

====
+

NOTE: O nome do host do vCenter é o nome da instância do vCenter Server onde o dispositivo de ferramentas ONTAP está implantado.

+
Se você estiver implantando ONTAP tools em uma topologia com dois vCenter Server, onde o appliance está hospedado em uma instância vCenter e gerencia outra, atribua uma função restrita para a instância vCenter que hospeda ONTAP tools. Crie um usuário e uma função dedicados no vCenter com apenas as permissões necessárias para a implantação do template OVF. Para detalhes, consulte link:../concepts/rbac-vcenter-use.html#vsphere-object-hierarchy["Funções incluídas nas ferramentas do ONTAP para VMware vSphere 10"].

+
Para a instância do vCenter gerenciada pelas ONTAP tools, certifique-se de que a conta de usuário do vCenter tenha privilégios de administrador.

+
** Os nomes de host devem incluir letras (A-Z, a-z), dígitos (0-9) e hífens (-). Para dual stack, especifique o nome do host mapeado para o endereço IPv6.
+

NOTE: O IPv6 puro não é suportado. O modo misto é suportado com uma VLAN que contenha endereços IPv6 e IPv4.

** O endereço IP do ONTAP tools (anteriormente load balancer) é o endpoint externo para o ONTAP tools Manager (`\https://<ip>:8443/virtualization/ui/`, chamadas de API e acesso ao plug-in a partir da interface do usuário do vCenter.
** O endereço IP virtual das ONTAP tools (anteriormente interconexão de nó) é atribuído ao servidor da API do Kubernetes (kube-api) e atua como o IP virtual para o plano de controle do Kubernetes.
** O endereço IPv4 é o endereço de gerenciamento do nó mapeado para o nome do host especificado e é usado para acesso ao shell de diagnóstico e SSH.


. Revise os detalhes na janela *Pronto para concluir*, selecione *concluir*.
+
Quando a tarefa de implantação é iniciada, o progresso é exibido na barra de tarefas do vSphere.

. Se você não selecionou a opção de ligar automaticamente, ligue a máquina virtual após a conclusão da tarefa.


Acompanhe o progresso da instalação a partir do console web da máquina virtual.

Se houver discrepâncias no formulário OVF, uma caixa de diálogo solicitará ações corretivas. Use a tecla Tab para navegar, faça as alterações necessárias e selecione *OK*. Você tem três tentativas para resolver os problemas. Se os problemas persistirem após três tentativas, a instalação será interrompida e você deverá tentar novamente a instalação em uma nova máquina virtual.
